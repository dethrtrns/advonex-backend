Schema Improvement Suggestions

Here are some suggestions to improve your database schema, including the one you mentioned:

  1. Normalize `PracticeCourt`

    Problem: As you correctly pointed out, the `PracticeCourt` model currently combines `name` and `location`, leading to data redundancy. For example, "High Court" might be repeated for many different locations.

    Suggestion: Split `PracticeCourt` into two distinct models: `CourtType` and `Location`. Then, create a new `Court` model that links a `CourtType` with a `Location`. This creates a more normalized and scalable structure.

    • `CourtType`: Stores the type of court (e.g., "Supreme Court", "High Court", "District Court").
    • `Location`: Stores geographical locations (e.g., "Delhi", "Mumbai", "Bangalore").
    • `Court`: A join table that represents a specific court instance, like the "High Court" in "Delhi".

  2. Simplify Lawyer Specialization and Primary Court

    Problem: The `LawyerProfile` has both a direct one-to-many relation (`specialization`, `primaryCourt`) and a many-to-many relation (`practiceAreas`, `practiceCourts`) for the same concepts. This is redundant and can be simplified.

    Suggestion: Remove the direct one-to-many relations. Use the existing many-to-many join tables (`LawyerPracticeArea`, `LawyerPracticeCourt`) and add a boolean flag (e.g., `isSpecialization` or `isPrimary`) to them. This indicates if a particular area is a specialization or if a court is the lawyer's primary court, while keeping the data structure clean.

  3. Consolidate OTP Models

    Problem: You have two separate models, `PhoneOtp` and `EmailOtp`, which are very similar in structure and purpose.

    Suggestion: Merge them into a single `Otp` model. This new model would have a `type` field (an enum of `EMAIL` or `PHONE`) and a `target` field (a string to store the email address or phone number). This reduces redundancy and simplifies the logic for handling OTPs.

  4. Standardize Naming and Relations

    Problem: Some relation names could be more explicit, and naming could be more consistent.

    Suggestion: I'll adjust some field and relation names for clarity and consistency. For example, renaming `userRoles` on the `User` model to just `roles` is more conventional.

// --- Core Authentication & Profiles ---

model User {
  id            String        @id @default(uuid())
  phoneNumber   String?       @unique
  email         String?       @unique
  accountStatus AccountStatus @default(ACTIVE)
  createdAt     DateTime      @default(now())
  updatedAt     DateTime      @updatedAt
  lastLogin     DateTime?

  clientProfile ClientProfile?
  lawyerProfile LawyerProfile?
  refreshTokens RefreshToken[]
  roles         UserRole[]
}

model UserRole {
  id        String   @id @default(uuid())
  role      Role
  isActive  Boolean  @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  user      User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  userId    String

  @@unique([userId, role])
  @@index([userId])
}

model ClientProfile {
  id                  String                @id @default(uuid())
  name                String?
  photo               String?
  registrationPending Boolean               @default(true)
  createdAt           DateTime              @default(now())
  updatedAt           DateTime              @updatedAt
  user                User                  @relation(fields: [userId], references: [id], onDelete: Cascade)
  userId              String                @unique
  savedLawyers        SavedLawyer[]         @relation("ClientSaves")
  sentRequests        ConsultationRequest[] @relation("ClientRequests")
}

model LawyerProfile {
  id                  String                @id @default(uuid())
  name                String?
  photo               String?
  experience          Int?

  consultFee          Int?

model Location {
  id        String   @id @default(uuid())
  name      String   @unique // e.g., "Delhi", "Mumbai"
  state     String?
  country   String   @default("India")
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  courts    Court[]
}

model CourtType {
  id        String   @id @default(uuid())
  name      String   @unique // e.g., "Supreme Court", "High Court"
  createdAt DateTime @default(now())

  courts    Court[]

model Court {
  id          String        @id @default(uuid())
  locationId  String
  courtTypeId String
  createdAt   DateTime      @default(now())
  updatedAt   DateTime      @updatedAt
  location    Location      @relation(fields: [locationId], references: [id], onDelete: Restrict)
  courtType   CourtType     @relation(fields: [courtTypeId], references: [id], onDelete: Restrict)
  lawyers     LawyerCourt[]

  @@unique([locationId, courtTypeId])
}

model LawyerCourt {
  lawyerProfileId String

  isPrimary       Boolean  @default(false) // New field

  court           Court         @relation(fields: [courtId], references: [id], onDelete: Cascade)

  @@id([lawyerProfileId, courtId])
  @@index([courtId])
}

  responseReason    String?
  clientProfile     ClientProfile  @relation("ClientRequests", fields: [clientProfileId], references: [id], onDelete: Cascade)
  lawyerProfile     LawyerProfile  @relation("LawyerRequests", fields: [lawyerProfileId], references: [id], onDelete: Cascade)

  @@index([clientProfileId])
  @@index([lawyerProfileId])
}

// --- Authentication Support ---

// NEW: Consolidated OTP Model
model Otp {
  id        String   @id @default(cuid())
  target    String   // Phone number or email address
  type      OtpType  // EMAIL or PHONE
  otp       String
  expiresAt DateTime
  isUsed    Boolean  @default(false)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([target, type])
  @@index([expiresAt])
}

model RefreshToken {
  id          String   @id @default(uuid())
  hashedToken String
  userId      String
  expiresAt   DateTime
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@index([userId])
}
